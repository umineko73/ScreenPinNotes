# 付箋の状態遷移と保存

## 表示モード

`StickyNoteWindow.StateTransitions.cs` の `TransitionTo` が、折りたたみ・閲覧・本文編集・タイトル編集の要求を受け付ける。UIイベントからは `ToggleFold` / `EnterEditMode` / `EnterTitleEditMode` / `EnterViewMode` を呼び、Coreメソッドを直接呼ばない。

1. 終了済みウィンドウと編集ロックを確認する。
2. 進行中の折りたたみアニメーションを確定する。
3. 必要なら展開し、その完了後に編集へ移る。
4. 目的の表示を適用する。

これにより、展開途中の高さを編集サイズとして扱ったり、編集サイズを古いアニメーションが上書きしたりしない。折りたたむ際の編集終了は、折りたたみ処理内で行う。編集終了が抑止されている場合は折りたたみも中止する。

タイトル表示・タイトル文字サイズ・画像に合わせたサイズ変更も、先に `CompleteFoldAnimation` を呼ぶ。高さの `BeginAnimation` は `StickyNoteWindow.Fold.cs` だけが所有する。新しいサイズ変更操作でも、途中の高さを読み取る前に完了させること。

`DisplayMode` は遷移先を指定するための列挙型。永続化する折りたたみ設定と実行中の編集状態を別の状態変数へ複製するものではない。WPFのレイアウト、フォーカス、表示適用は引き続きViewが担当する。

## 保存

自動保存・編集終了・ウィンドウを閉じる処理は `FlushPendingSave`、アプリ全体の保存は `App.SaveAll` から、同じ `StickyNoteWindow.SaveNote` に到達する。書き込みはコンストラクターで渡された `StorageService.SaveNote` を使う。

- 自動保存は対象の付箋だけを書き込む。
- 全件保存は各ウィンドウの `SaveNote` を呼び、保留フラグとタイマーも解消する。
- 書き込み成功後にだけ保留状態を解除する。失敗した内容は再試行できる。
- 削除に成功した付箋は `DisableSaving` でタイマーと以後の保存を停止してから閉じる。遅延保存による復活を防ぐ。
- 保存先の切り替えでは既存のウィンドウ再生成を維持し、新しい保存先を渡す。

設定への `App.Current` 参照や、アプリによるウィンドウ一覧の管理は今回変更していない。アプリ全体のMVVM移行ではなく、表示遷移と付箋保存の経路を統一した変更である。

## テスト

- `StickyNoteWindowTests`：通常往復、連続切り替え、編集開始コールバック、位置・サイズ・日本語本文の保持。
- `NoteTransitionRegressionTests`：展開中の本文／タイトル編集、タイトル表示／文字サイズ変更、非表示付箋へのスナップ除外。
- `NotePersistenceTests`：アプリへの登録なしで注入先へ保存、保存失敗後の再試行、削除後の保存抑止。
- `AppNoteWindowTests`：実タイマーによる自動保存、Undo／Redo、新規作成、非表示、リマインダーとの連携。

これらはWPF上の自動テストであり、実マウス入力や日本語IMEの候補選択を検証するE2Eテストとは区別する。
