## 再現した問題

### アニメーション中の再切り替えで位置または展開高さが崩れる

タイトルバーあり／なしの双方で再現。個別テストと全件テストの2回で、同じ4条件が失敗した。

前提：アニメーションを有効にし、展開位置を (180,180)、1行表示位置を (90,100)、位置を分離、展開サイズを420×320、1行表示の幅を230にする。

| 開始状態 | 操作 | 期待値 | 全件実行での実測 |
| --- | --- | --- | --- |
| 展開・タイトルあり | 折りたたみ開始から30ms後に再展開 | 展開位置X=180 | X=90 |
| 展開・タイトルなし | 折りたたみ開始から30ms後に再展開 | 展開位置X=180 | X=90 |
| 1行・タイトルあり | 展開開始から30ms後に再度折りたたみ | 保存された展開高さ=320 | 約246.1 |
| 1行・タイトルなし | 展開開始から30ms後に再度折りたたみ | 保存された展開高さ=320 | 約231.9 |

途中の高さの実測値はフレームのタイミングによって変わる。最初の不一致でテストが停止するため、表にない後続アサーションの成功を意味しない。

テスト名：`RapidFoldRoundTrip_PreservesExpandedHeight`。

修正前の原因：`StickyNoteWindow.Fold.cs` の `ToggleFold` は、前のアニメーション完了前でも次の切り替えに入り、現在の座標・幅・高さをモデルに取り込んでいた。展開中に折りたたむと `_unfoldedHeight = Height` が途中の高さを記憶する。また、折りたたみ完了時に位置と幅を設定するコールバックがあり、重複した切り替えに対する調整がなかった。

ユーザー報告の「タイトルなしの1行／展開位置を記憶できない」と同一かは未確定。アニメーション無効時の通常往復では再現しなかった。実際の操作順、Ctrlの有無、ドラッグ開始位置の確認が必要。

既存372件には、本文編集・コンテキストメニュー・パレット・編集ロック・読み取り専用／外部ファイル・画像・Markdown・検索・保存・リマインダー・ホットキーなどのテストが含まれ、今回の全件実行でも合格している。これは各機能の実操作すべてを確認したという意味ではない。

## 実画面検証の制約と残作業

Computer Useを初期化して対象を列挙したが、起動したScreenPinNotesのウィンドウが返されなかった。直接起動でも `launched app did not expose a targetable window` が返った。タスクバー表示を有効にした別のテスト環境でも検出できなかった。プロセスの存在とテスト用データ生成は確認できたが、実画面の状態は確認できていない。

そのため、以下は未検証であり、徹底的な実操作テストの完了とは扱えない。

- タイトル／本文／右上操作エリアからの実マウスドラッグ、Ctrl・Alt併用、キャプチャ解除、スナップ、画面間移動。
- 実キーボードによるCtrl+Enter・コピー／切り取り／貼り付け、Tab移動、ショートカット競合。
- 日本語IMEのローマ字入力、候補選択、変換確定・取消、再変換、変換中のEnter／Esc、変換中の自動保存やフォーカス移動。
- 実画面での文字欠け、変換候補ウィンドウの位置、DPI混在・複数モニター。

実画面を操作可能にした後、上記をタイトル有無×1行／展開×編集／閲覧（編集は展開時）で確認し、既知の位置記憶問題の操作順と照合する。
